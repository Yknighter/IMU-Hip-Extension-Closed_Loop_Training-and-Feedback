# IMU Hip Extension Feedback V19.9v

App 版本：`1_19_9vibrant`；build：`901900`。本版基于 v19.8 增加丢包、数据滞后保护和恢复后的中立位重新就绪。

## 安装与运行

1. 停止旧 Hub App，导入 `IMU_Hip_Extension_Feedback_v1_19_9vibrant.zip`，选择 **IMU Hip Extension Feedback V19.9v**，核对描述中的 build 901900。
2. 四个采集节点依次为 `right_thigh`、`left_thigh`、`pelvis`、`vibration_monitor`；独立反馈列表为空，同一颗节点只绑定一次。
3. 查看器在电脑运行：将 `Fast_IMU_Training_Viewer_v19_9.zip` 解压至同一文件夹，双击 `start_v19_9_viewer.cmd` 或 `開啟V19_9vibrant查看器.cmd`。窗口标题应为 V19.9v。
4. 在 Hub 页面点击 Start，先自然站立，连续稳定 2 秒完成校准，再按提示回中立位重新就绪，之后进行默认 60 秒能力评估和训练。

App 导入包只供 Hub 使用；查看器包在 Windows 电脑解压运行。查看器源码、启动脚本和 verification 测试目录位于本 App 目录的上一级。

查看器需要 Python 3、Tkinter、websocket-client。启动脚本优先使用 C:\Python39\python.exe，否则使用 PATH 中的 python。默认 Hub IP 为 192.168.137.1，WebSocket 5678，状态 API 80。可以通过 `start_v19_9_viewer.cmd --hub-ip 其他IP` 指定地址。

## 缺帧之后的反馈规则

- 检查四个节点的 Sampletime、Package、接收间隔和估计缓存滞后。缺帧、重复包、包号异常、无效姿态或过期数据均暂停新奖励。
- 清除正在累计的达标时间、中立位时间、滤波窗口和未完成的峰值片段。中断片段不算成功，也不算失败；已经完成的训练计数及当前目标保留。
- 缓存中的旧包仍按 SDK 可保存的完整帧记录，但不进入姿态滤波、评估统计或奖励判定。缺失的原始帧不会被插值或伪造。
- 恢复后先用全新的有效帧填满默认 5 点移动平均窗口，再要求有符号后伸角 E <= 0 连续保持 200 ms。中途再次缺帧或离开中立位就重新计时。
- 重新就绪后，下一次动作需重新满足 E >= T 连续 30 ms 才奖励一次。不会把丢包前的 20 ms 与恢复后的 10 ms 拼接，也不补发过期奖励。
- 中立位就绪只要求一次 200 ms，不会在解锁之后再额外等待第二个 200 ms。
- 连续时间使用展开后的传感器时间；发送震动前再次检查新鲜度，防止计算过程变慢后继续用旧帧发命令。

例：目标 10 度，达到 12 度并保持 20 ms 后缺帧，恢复时仍为 12 度，这次不震动。先回中立位连续保持 200 ms，再进行一次新的、连续达标 30 ms 的后伸，才能获得奖励。

## 工程参数与边界

默认采样率 100 Hz。以下固定设置保存在 config.json，不逐帧重复写入：

- `data_gap_max_period_factor=1.5`：相邻时间戳超过标称采样周期的 1.5 倍视为缺帧；100 Hz 下为超过 15 ms。
- `data_freshness_max_lag_sec=0.05`：估计额外缓存滞后超过 50 ms 时禁止反馈。
- `data_receive_timeout_sec=0.1`：相邻收包间隔超过 100 ms 时中断当前动作，即使之后收到的包看起来数值正常。

这些是离线验证使用的工程初始值，尚需按实际 Hub、时钟抖动和负载验证。新鲜度估计是相对首次收到数据的额外滞后，不是经仪器标定的绝对传输延迟。开始试次时调用 clear_buffered_data 清除试次前的 SDK 缓存；中断后不重新对齐时钟基准，避免将旧包重新当成新数据。

Sampletime 按已有实测通道的 16 位毫秒时钟处理，正常回绕不会被判为缺帧。Package 正向不连续或重复会中断；由于官方未明确包号位宽，仅在时间戳连续时接受包号回到 0。时钟倒退或超过半个时钟周期的长时间失联会锁住反馈，需要停止并重新启动 App。

本版保留四路同步采集，不能修复节点无线掉线或 Hub 驱动失同步。SDK 取数阻塞时没有新帧参与奖励，返回后会检查间隔与滞后；本次未添加并发调用 SDK 的独立停震线程。断连后的电机实际停震仍需验证节点固件行为。

## 保存与查看

默认 CSV；保留原 155 个动态字段，新增 10 个动态诊断字段，总计 165 个。固定设置仍不逐行记录。

- `data_fresh_state`：1 表示该帧通过连续性和滞后检查；0 表示禁止用于实时反馈。
- `data_gap_event`、`data_gap_count`：一次连续中断的首次事件及累计次数。
- `data_gap_reason`：0 正常，1 时钟缺失或无效，2 重复包，3 时钟倒退或歧义，4 时间戳缺帧，5 包号异常，6 数据滞后，7 接收超时，8 姿态无效。
- `data_gap_duration_sec`：最近一次中断的缺口、接收间隔或滞后估计，取决于原因；不能统一解释为精确丢包时长。
- `data_lag_sec`、`data_receive_interval_sec`：估计额外滞后与本次收包间隔。
- `feedback_recovery_state`：0 数据不可用，1 等待滤波预热或中立位重新就绪，2 已就绪。
- `feedback_recovery_neutral_sec`：恢复阶段已连续保持中立位的时间。
- `interrupted_episode_count`：因中断而取消的未完成动作数。

`time` 改为传感器时钟展开后的相对时间，保留缺口，不再将每次收到的帧都机械地增加 10 ms。查看器对无效角度显示空缺，蓝线不会跨缺口直接相连；绿线为目标，红点仍是震动命令记录，不能视为物理电机响应确认。

原有实测通道保留原始三轴加速度、传感器与 Hub 到达时钟、RMS 和命令事件。RMS 阈值默认 0，仅记录信号，实测状态未知；100 Hz 加速度不能保证识别所有电机振动。

## 默认奖励与训练

中立位 200 ms 后重新允许下一次动作；后伸达到目标连续 30 ms 发出一次奖励，默认 0.2 秒、强度 2，请求时长最大 0.25 秒。目标升级不额外震动。

能力评估采用有效片段峰值的第 75 百分位并向下取整，默认目标范围 1 至 15 度。训练窗口默认 60 秒，至少 8 个有效片段且峰值达标率达到 80% 时目标增加 1 度。中断及恢复门控期间不推进评估或训练的有效样本计时。

本次仍使用现代 sensor_vibration_on/off 接口，增加对 clear_buffered_data 的启动检查。历史字段 adaptive_eval_target_phase_sec 在训练模式下继续表示有效片段计数，仅输出类型为 float。
